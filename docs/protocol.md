# Protocol evidence and compatibility

Verified on 2026-11-17 against the [official app-server documentation](https://learn.chatgpt.com/docs/app-server)
and JSON schema generated by the official npm CLI **0.169.0**:

```sh
npx --yes @openai/codex@0.169.0 --version
npx --yes @openai/codex@0.169.0 app-server generate-json-schema --out /tmp/codex-schema
```

The target installation could not be inspected: `codex` was absent from PATH and no live
endpoint was supplied. Downloading this reference CLI does not establish the app's version.
Run these commands with the actual deployment binary before deploying. The implementation
fails on missing methods or malformed required fields rather than reading internal storage.
The daemon never directly accesses Codex databases, rollouts, or session files.

## Interface contract

- JSON-RPC omits the `jsonrpc` header. One receive loop handles responses, notifications,
  and server requests. `initialize`/`initialized` run once per connection.
- Transports: standard WebSocket frames over TCP/TLS or a configured Unix socket with HTTP
  Upgrade. Explicit stdio command uses JSONL. There is no guessed default socket discovery;
  configure the concrete path. The packaged default is only a placeholder.
- `thread/list`: walk `nextCursor` to null separately for `archived=false` and `true`;
  `modelProviders=[]` explicitly includes all providers. Omitted/empty `sourceKinds`
  means only interactive sources, so all ten schema enum values are explicitly supplied.
  No cwd, section, relationship, or originator restriction is added. Scope remains whatever
  the server/account/storage permits discovery and reading. Future source enum additions
  require updating `history.SOURCES` after schema verification.
- `thread/read`: metadata only, without resuming or subscribing to the source. Only `name`
  is eligible; null/missing names never fall back to `preview`.
- `thread/turns/list`: ascending pages with `itemsView=full`, not the summary default.
  Full view supplies full item details without output deferral. The separate
  `thread/items/list` API exists but is not required by this full-turn path. A response
  explicitly reporting a non-full view is rejected. No acquisition succeeds after a failed
  page. This intentionally requires the modern paginated API, without legacy fallback.
- `thread/name/updated`: `threadId`, nullable `threadName`. Additive notifications are ignored.
  The documentation says name-setting emits this notification but does **not** promise that
  a passive connection receives every other client's name update. Source reads do not
  subscribe. Global cross-client delivery has not been established; rely on reconciliation
  for names that remain long. A separate stdio server does not inherit app notifications.
- `model/list`: paginate with hidden models included, require exact model ID and advertised
  `supportedReasoningEfforts[].reasoningEffort=low`. No fallback. This API does not establish
  the effective context budget.
- `thread/start`: ephemeral, dedicated base/developer instructions, read-only sandbox,
  no approvals; verify returned model. `turn/start`: explicit model, effort and JSON Schema.
  Accept only a completed turn's final agent message, rejecting reroutes and tool activity.
- `thread/name/set`: `threadId`, `name`; no conditional update/revision field in this schema.
  Read-before-write is inherently racy. Uncertain writes are read back, never blindly replayed.
- Cleanup uses helper-only `turn/interrupt` and `thread/unsubscribe`; ephemeral storage and
  server inactivity unloading handle helper lifetime. There is no invented thread-delete API.

Helper config keys were inspected in the official
[0.169.0 configuration schema](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/config.schema.json).
Web search, shell/unified execution, apps, collaboration, code mode, image/browser/computer
and patch features are disabled where supported. Configured MCP server names from
`config/read` are disabled for helpers. Dedicated instructions replace ordinary base
instructions; environment context is disabled. Managed policies may reject overrides;
there is no bypass. This does not establish that every possible server-side tool or inherited
instruction is disabled. Server-initiated requests receive an unsupported-method error.
Any observed helper tool item disqualifies its result.

## Unrun deployment checks

1. Inspect the owning server version, generate its schema, and compare the contract above.
2. Connect to its actual socket/auth endpoint and confirm initialization, account visibility,
   archived/source/provider listing, full-history pagination and large-response limits.
3. Confirm whether name notifications reach a passive connection across clients.
4. Verify model availability, effective context/compaction limits, configuration override
   behavior under managed policies, and helper-only cleanup after cancellation/disconnect.
5. On synthetic disposable threads only, assess multilingual title quality, reroutes,
   completed-message phases, and uncertain rename behavior. Do not test on user conversations.

The offline tests are deterministic protocol/workflow checks, not proof of live model quality
or compatibility with an uninspected target application.
